# Identity database / مدیریت افراد

`HshDetectionEngin.Identity` مالک SQLite مشترک هویت‌هاست. یک فایل
`identity-database.db` جدول اصلی `People` را نگه می‌دارد و هر modality اطلاعات
اختصاصی خودش را در جدول جدا ذخیره می‌کند:

- `People`: نام، شمارهٔ شخص، وضعیت ناشناس و زمان ایجاد/ویرایش.
- `PersonPlates`: پلاک‌های متعلق به شخص؛ هر پلاک normalized و یکتا است.
- `FaceSamples`: تصویر crop‌شده، embedding، confidence و metadata مدل چهره.
- `PalmSamples`: تصویر normalized، embedding، confidence و metadata مدل کف دست.

هر شخص می‌تواند چند پلاک، چند نمونهٔ چهره و چند نمونهٔ کف دست داشته باشد و
ارتباط همهٔ آن‌ها با `PersonId` انجام می‌شود. برای modality جدید باید جدول و
adapter مستقل اضافه شود؛ ستون‌های modality-specific نباید به `People` اضافه
شوند.

برنامهٔ Windows و `HshDetectionService` این فایل را باز می‌کنند. هنگام بارگذاری
دیتابیس مرکزی، داده‌های legacy از `face-database.db` و `palm-database.db` به‌صورت
مستقل بررسی و با حفظ نمونه‌ها وارد می‌شوند؛ بنابراین وجود قبلی افراد Face مانع
ورود افراد یا نمونه‌های Palm نمی‌شود. migration با نام یا شمارهٔ شخص موجود را
به همان `PersonId` مرکزی متصل می‌کند و نمونهٔ تکراری را دوباره وارد نمی‌کند.

رابط وب این storage را با عنوان `مدیریت افراد` (`/faces`) نمایش می‌دهد. برای هر
شخص سه تب مستقل `چهره`، `پالم` و `پلاک` وجود دارد. شخصی که فقط نمونهٔ Palm دارد
نیز در فهرست قابل مشاهده است؛ cropهای ناشناس runtime با نام‌هایی مانند
`Unknown Palm #0001` نگه‌داری می‌شوند تا بعداً به شخص نام‌دار منتقل شوند.

حذف شخص از `People` به‌صورت آبشاری نمونه‌های `FaceSamples`، `PalmSamples` و
`PersonPlates` را نیز حذف می‌کند. حذف تکی و حذف گروهی از همین قانون استفاده
می‌کنند؛ حذف گروهی فهرست `PersonId`ها را می‌گیرد و تعداد رکوردهای حذف‌شده را
برمی‌گرداند.

در اجرای زنده، Face و Palm ابتدا matchهای نام‌دار را جست‌وجو می‌کنند و سپس
با threshold جداگانهٔ unknown، نمونه‌های ناشناس قبلی را مقایسه می‌کنند. اگر
match ناشناس وجود نداشته باشد، شخصی مانند `Unknown Palm #0001` ساخته و crop و
embedding آن ذخیره می‌شود؛ سقف نمونه و فاصلهٔ زمانی ثبت ناشناس برای جلوگیری از
ثبت تکراری اعمال می‌شود.
