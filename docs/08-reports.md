# استاندارد عمومی گزارش‌ها و خروجی‌ها

فهرست گزارش‌های Home، نام نمایشی، کلید route، گروه‌بندی، workspace، endpoint و وضعیت اتصال آن‌ها در [سند مرجع Home وب](25-home.md) ثبت شده است. این سند فقط قواعد عمومی قابل استفاده برای گزارش‌های نسخه وب و ویندوز را نگه می‌دارد.

## زبان ابزارهای نمایشگر وب — ۲۰۲۶/۱۱/۱۳

**رفتار پیاده‌شده:** زبان نوار ابزار و پنجره‌های داخلی موتور گزارش از همان منابع مشترک `i18next` برنامه خوانده می‌شود؛ راست‌به‌چپ‌کردن به‌تنهایی کافی نیست. منابع `locales/reportViewer/fa.ts` و `en.ts` زیر کلید `reportViewerEngine` ثبت شده‌اند و ۴۱۸ متن مورد نیاز Viewer نسخهٔ نصب‌شده را پوشش می‌دهند: چاپ، ذخیره، صفحه‌بندی، بزرگ‌نمایی، جست‌وجو، راهنمای ابزارها، تنظیمات خروجی، تاریخ و پیام‌ها. نام قالب‌های فنی مانند PDF حفظ می‌شود.

`reportViewerLocalizationXml` منابع مشترک را با escape محتوا به XML مورد انتظار SDK تبدیل می‌کند. `useReportViewerOptions` در lifecycle کنترل‌شدهٔ React، پیش از ساخت گزینه‌ها و mount نمایشگر، API عمومی `StiLocalization.setLocalization` را فراخوانی می‌کند. با تغییر زبان، Viewer بازسازی و انگلیسی نیز صریحاً اعمال می‌شود تا ترجمهٔ فارسی قبلی در موتور باقی نماند. ترجمهٔ شرطی داخل component، تغییر مستقیم DOM، دریافت شبکه‌ای فایل زبان یا سامانهٔ ترجمهٔ مستقل اضافه نشده است.

منبع اولیهٔ بخشی از فارسی، [منابع رسمی ترجمهٔ موتور](https://github.com/stimulsoft/Stimulsoft.Reports.Localization/blob/master/fa.xml) است؛ موارد ناقص و عبارت‌های نامناسب تکمیل و اصلاح شده‌اند. مرجع نگهداری و تغییر متن در برنامه همان منابع `i18next` است. آزمون تطبیق با کلیدهای درخواستی SDK باید پس از ارتقای موتور اجرا شود؛ نبود کلید، عدم تطابق جای‌نگهدارهای `{0}` یا باقی‌ماندن متن انسانی فاقد ترجمه، خطای تست است. این تغییر شامل ترجمهٔ داده‌های دریافتی از API یا بازنویسی عنوان‌های داخل قالب MRT نیست.

## فیلترهای عمومی

**تصمیم محصول / رفتار پیاده‌شده — ۲۰۲۶/۱۱/۱۳:** هر فیلتر ورود پلاک در گزارش‌ها باید از `IranianPlateInput` مشترک استفاده کند؛ `TextField` متنی مستقل یا mask اختصاصی مجاز نیست. اکنون گزارش تردد خودروها (`traffic-reports-list`)، درآمد پارکینگ آزاد مدیریتی (`management-free-parking-income`) و جزئیات حمل بار (`cargo-details`) این کنترل را با زبان صریح صفحه و عنوان/پیام اعتبارسنجی از منابع `reportFilters` در i18next مصرف می‌کنند. گزارش‌های فاقد فیلتر پلاک ورودی جدید نمی‌گیرند.

فیلتر اختیاری است: مقدار خالی با `Plate: ''` ارسال می‌شود؛ مقدار غیرخالی باید با `isValidIranianPlate` و قالب انتخاب‌شده کامل باشد، وگرنه پیام ترجمه‌شده نمایش داده می‌شود و درخواست گزارش ارسال نمی‌شود. مقدار ارسالی، canonical با ارقام لاتین است؛ برای خودرو مانند `12ب34567` و برای موتور مانند `12345678`. تغییر قالب، مقدار قبلی را طبق رفتار مشترک پاک می‌کند. انتخاب قالب در کنترل پلاک، فیلتر مستقل «نوع خودرو» در گزارش تردد و درآمد آزاد را تغییر نمی‌دهد؛ endpointها و سایر فیلدهای payload حفظ شده‌اند.

قاب مشترک `report-plate-filter` به‌اندازهٔ محتوای کنترل و در ابتدای سلول فیلتر قرار می‌گیرد؛ دیگر دو ستون با عرض کشیده اشغال نمی‌کند. خود کنترل در دسکتاپ و موبایل و برای خودرو/موتور همیشه اندازهٔ پیش‌فرض **۱۹۰×۵۶ پیکسل** دارد. فیلتر هنگام دریافت گزارش غیرفعال است. متن‌های داخلی، پیمایش کیبورد و قرارداد نمایش از [کامپوننت مشترک](10-shared-ui-components.md) می‌آیند. فیلدهای فقط‌خواندنیِ پلاک در خود خروجی گزارش، مشمول الزام ورود نیستند. منابع اجرا: سه workspace یادشده، `styles.css` و `tests/e2e/report-plate-filter.spec.ts`.

بسته به نوع گزارش، فیلترها می‌توانند شامل موارد زیر باشند:

- تاریخ و ساعت شروع و پایان؛
- پارکینگ؛
- درب؛
- نوع تردد؛
- نوع خودرو؛
- عضو یا کاربر؛
- نمایش تصویر، در صورت پشتیبانی گزارش.

هر filter panel باید schema و validation مشخص داشته باشد و حالت‌های loading، empty، error و unauthorized را مدیریت کند.

## نمایش و خروجی

- گزارش وب در پیش‌نمایش تمام‌صفحه و با حفظ فیلترهای صفحهٔ مبدا نمایش داده می‌شود؛
- چاپ و export فقط در صورت وجود قرارداد و پشتیبانی واقعی viewer مجاز است؛
- قالب‌های گزارش موجود در `EosParkingTools/EosControls/ReportDesign` منبع legacy هستند و استفاده از آن‌ها در وب نیازمند تطبیق binding است؛
- قالب‌های قدیمی که از `MainTable` یا expressionهای legacy استفاده می‌کنند باید در لایه وب به DataTable واقعی نگاشت شوند؛
- گزارش نباید با داده mock یا موفقیت ساختگی به‌عنوان قابلیت واقعی معرفی شود.

## پیش‌نمایش تمام‌صفحهٔ وب — ۲۰۲۶/۱۱/۱۳

**تصمیم محصول / رفتار پیاده‌شده:** گزارش‌های اعضا، تردد، مالی، مدیریتی و حمل بار پس از دریافت داده و پایان `renderAsync2` در `ReportPreview` مشترک و `AppPopup fullScreen` باز می‌شوند. فیلترها در workspace مبدا می‌مانند؛ پیش‌نمایش فقط یک نتیجهٔ آماده را نمایش می‌دهد و endpoint تازه یا درخواست تکراری برای بازشدن ندارد. قالب MRT، binding داده، محاسبات، مجوز route و payload گزارش تغییر نکرده‌اند. این قرارداد مربوط به Viewerهای وب موجود است؛ وضعیت اتصال هر گزارش همچنان در [سند Home](25-home.md) مرجع است.

| حالت / اقدام | رفتار فعلی |
|---|---|
| دریافت API یا رندر | فیلترها و وضعیت انتظار موجود حفظ می‌شوند؛ پیش‌نمایش برای report ناموجود باز نمی‌شود. |
| نتیجهٔ آماده | پنجره خودکار باز می‌شود؛ عنوان، تعداد رکورد و بستن در سربرگ ثابت‌اند. نتیجهٔ صفر رکورد نیز گزارش معتبر است. |
| خطای دریافت یا رندر | پیام خطای workspace باقی می‌ماند؛ بدون report آماده پنجره‌ای باز نمی‌شود. |
| بستن یا Escape | فقط نمایشگر بسته می‌شود؛ فیلترها، داده و شیء گزارش در state همان workspace باقی می‌مانند. |
| نمایش دوباره گزارش | همان نتیجه در پنجره باز می‌شود؛ API و رندر قالب دوباره اجرا نمی‌شوند. دکمه هنگام دریافت/رندر غیرفعال است. |
| اجرای گزارش تازه | مسیر موجود دریافت و رندر اجرا می‌شود و نتیجهٔ آمادهٔ جدید دوباره خودکار باز می‌شود. |
| تغییر فیلتر پس از بستن | بازسازی قالب با همان دادهٔ قبلی، پنجره را خودکار باز نمی‌کند؛ فقط نتیجهٔ تازهٔ درخواست گزارش یا «نمایش دوباره گزارش» باعث بازشدن می‌شود. |
| ترک workspace / reload | نگهداری نتیجه در storage یا بین نشست‌ها اضافه نشده است؛ حفظ نتیجه فقط تا عمر همان workspace است. |

قاب پنجره ارتفاع `100dvh` دارد؛ سربرگ از فضای محتوای گزارش جداست و بخش باقی‌مانده با `flex` و `min-height:0` اندازه می‌گیرد. حداقل ارتفاع ۵۲۰ پیکسلی و محاسبهٔ ثابت `100vh - 330px` از پنج workspace حذف شده‌اند. عنصر ریشهٔ React Viewer نیز ارتفاع صریح ۱۰۰٪ دارد تا محاسبهٔ ارتفاع موتور به فضای واقعی محدود شود. اسکرول در پنل داخلی گزارش است و سربرگ/ابزارها با پیمایش صفحات پایین نمی‌روند. فارسی/انگلیسی و RTL/LTR از تنظیم زبان پیروی می‌کنند؛ بستن با کیبورد و کنترل focus از پوستهٔ مشترک پنجره استفاده می‌کند.

Viewer با `scrollbarsMode=true` و بزرگ‌نمایی اولیهٔ `PageWidth` ساخته می‌شود. نوار ابزار خودکار پنهان نمی‌شود؛ چاپ، خروجی، بزرگ‌نمایی و کنترل صفحات متعلق به خود موتورند. دکمهٔ fullscreen داخلی غیرفعال است تا پنجرهٔ تمام‌صفحهٔ دیگری روی قاب مشترک ایجاد نشود. بازکردن فایل گزارش و ارسال ایمیل فعال نشده‌اند. نمایش ابزار خروجی به‌معنای تأیید تمام فرمت‌ها، چاپگر واقعی یا درستی مالی دادهٔ سرور نیست؛ مجوز موتور، قالب و امکانات مرورگر همچنان مؤثرند.

در عرض کم، خود نوار ابزار موتور اسکرول افقی مستقل دارد؛ چاپ و خروجیِ خارج از عرض اولیه با پیمایش همان نوار در دسترس‌اند و صفحه یا سربرگ جابه‌جا نمی‌شود. محتوای گزارش همچنان از اسکرول داخلی موتور استفاده می‌کند.

منابع: `features/reports/ReportPreview.tsx` و `reportPreview.css`، یکپارچه‌سازی در پنج `*ReportWorkspace.tsx` و منابع `reportPreview` در `fa.ts/en.ts`. تست واحد `ReportPreview.test.tsx` چرخهٔ آماده/بستن/بازکردن/نتیجهٔ جدید، حالت null، صفر رکورد و زبان را بررسی می‌کند؛ تست مرورگر `tests/e2e/report-preview.spec.ts` با موتور واقعی و API شبیه‌سازی‌شده، پنجره، صفحهٔ کوتاه، موبایل، بازکردن بدون درخواست مجدد و خطا را بررسی می‌کند. نتیجه و محدودیت‌های اجرای واقعی آزمون در سند ۲۱ ثبت می‌شوند.

## قرارداد API گزارش

### وابستگی گزارش درآمد به نوع پارکینگ — ۲۰۲۶/۱۱/۱۳

**تصمیم محصول / رفتار پیاده‌شده:** دسترسی وب به گزارش‌های درآمد پارکینگ وابسته به تجاری‌بودن پارکینگ جاری است. فهرست شش گزارش، استثناها، رفتار منو و آدرس مستقیم، تغییر پارکینگ و حالت نامشخص در بخش «شرط تجاری‌بودن پارکینگ» [سند مرجع Home، بخش ۶](25-home.md) نگهداری می‌شود. این محدودیت ورود به workspace است؛ API، payload، قالب و فیلترهای داخلی گزارش تغییر نکرده‌اند. نتیجهٔ آزمون در سند ۲۱ ثبت شده است.

### تصاویر گزارش ورود و خروج خودروها — ۲۰۲۶/۱۱/۱۳

با فعال‌بودن «با تصویر»، درخواست موجود `GetTrafficReport` مقدار `Filters.WithImage=true` می‌فرستد و عکس هر رکورد از `EnterImage` همان ردیف خوانده می‌شود. در قالب وب، منبع ردیف‌ها `MainTable2` است؛ بنابراین اتصال `Image1.DataColumn` نیز هنگام آماده‌سازی قالب باید به `MainTable2.EnterImage` تبدیل شود. جاافتادن `Image1` از فهرست تبدیل اتصال‌ها باعث خالی‌ماندن تصاویر شده بود؛ این مورد در `TrafficReportWorkspace.tsx` اصلاح شد. فایل MRT، Backend و ساختار پایگاه داده تغییر نکردند.

رکوردی که `EnterImage` ندارد با خانهٔ تصویر خالی نمایش داده می‌شود. با برداشتن تیک، قالب بدون تصویر و درخواست `WithImage=false` استفاده می‌شود. آزمون `tests/e2e/traffic-report-images.spec.ts` با موتور واقعی گزارش و پاسخ API شبیه‌سازی‌شده، دو تصویر متفاوت در ردیف‌های مجزا، یک ردیف بدون عکس و اجرای دوباره بدون تصویر را بررسی می‌کند.

برای هر گزارش باید endpoint، method، request، response، status code، خطا، permission و محدودیت pagination مشخص باشد. تا زمان تأیید Backend، نام endpoint مشاهده‌شده از کد نباید به‌عنوان قرارداد کامل API تلقی شود.

کنترل visibility آیتم گزارش در UI جایگزین authorization سمت Backend نیست. پاسخ‌های `401` و `403` باید توسط API client و feature گزارش مدیریت شوند.

## نیازمندی عمومی نسخه وب

- دسته‌بندی خوانا و قابل جست‌وجوی گزارش‌ها؛
- filter schema قابل تنظیم برای هر گزارش؛
- نمایش loading، empty، error و unauthorized؛
- جدول، KPI یا نمودار متناسب با نوع گزارش؛
- حفظ فیلترها در refresh، retry و export؛
- پشتیبانی درست از فارسی/انگلیسی، RTL/LTR و دسترس‌پذیری.
